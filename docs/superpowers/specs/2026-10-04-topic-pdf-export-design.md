# 主题 PDF 导出设计

## 目标

为首页“主题入口”中的每个主题生成一份可离线阅读的 PDF。PDF 使用与首页相同的主题归类规则，包含该主题匹配到的全部页面，而不是卡片中展示的前四个精选链接。

## 方案选择

考虑三种实现：

1. 直接拼接 Markdown 后交给 Pandoc。实现简单，但会绕过现有 wikilink、标题 ID、表格和资源路径处理。
2. 让 PDF 工具抓取多个现有 HTML 页面。能复用页面输出，但页间导航、重复外壳和目录难以控制。
3. 在现有 Python 构建器中生成主题书 HTML，再用 WeasyPrint 转为 PDF。

采用第三种方案。它复用 `build.py` 的 frontmatter、Markdown 和 wikilink 解析，同时为打印输出提供独立、可测试的书籍结构。

## 主题与页面选择

- 为 `TOPIC_GROUPS` 中每个主题增加稳定的英文 `slug`。
- 页面匹配继续使用现有规则：页面标签与主题标签相交、标题包含主题 token，或页面位于主题的 `preferred` 列表。
- 去重后，先按 `preferred` 顺序排列精选页面，再排列其余匹配页面。
- 首页主题卡片仍只展示前四个精选入口，但计数和 PDF 使用完整匹配集合。
- 页面可以出现在多份主题 PDF 中；主题是阅读视图，不是互斥分类。

## 构建接口

扩展现有命令：

```bash
./wiki/html-assets/build.py --pdf-topic ai-agent-memory
./wiki/html-assets/build.py --pdf-topics
```

- `--pdf-topic SLUG` 生成指定主题。
- `--pdf-topics` 生成全部主题。
- 未指定 PDF 参数时，现有 HTML 构建行为保持不变。
- 未知 slug 返回非零退出码，并列出合法 slug。
- 找不到 WeasyPrint 时返回清晰错误，不影响普通 HTML 构建。

输出文件位于 `wiki/pdf/<slug>.pdf`。构建器同时生成临时的主题书 HTML，供 WeasyPrint 使用；成功后不把临时文件留在仓库中。

## PDF 结构

每份 PDF 按以下顺序组成：

1. 主题封面：标题、说明、生成日期和页面数量。
2. 目录：列出所有收录页面，并链接到对应章节。
3. 正文：每个 wiki 页面作为独立章节，从新页开始。

正文复用现有 Markdown 扩展，包括 fenced code、table、admonition、列表和标题 ID。主题书内的 wikilink在目标页面也被收录时改写为 PDF 内部锚点；未收录目标仍保留为可读文本，避免产生失效的本地 HTML 链接。图片使用绝对 `file://` 基础路径解析。

## 打印样式

新增独立的 print CSS，设置 A4 页面、中文字体回退、页边距、页码、章节分页、代码块换行和表格防溢出。网页顶部导航、侧边栏、主题切换和页脚导航不进入 PDF。

## 首页入口

每张主题卡片增加“下载 PDF”链接，指向 `pdf/<slug>.pdf`。链接只有一个稳定目标；仓库使用者运行 `--pdf-topics` 后即可获得全部文件。

## 测试与验证

- 单元测试覆盖主题 slug、完整页面集合、顺序、主题书内部链接与未知 slug。
- HTML 构建回归测试确认卡片包含正确的 PDF 链接。
- 实际运行单主题和全部主题导出，检查命令退出码、文件存在、PDF magic bytes 和非零文件大小。
- 运行普通 HTML 构建，确认现有 308 个页面构建路径不受影响。

## 非目标

- 不改变 `wiki/` Markdown 内容或主题归类规则。
- 不为任意搜索结果或知识图谱邻居集动态生成 PDF。
- 不提交临时主题书 HTML。
- 不在浏览器端即时渲染 PDF。
